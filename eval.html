01 / Pipeline

7 步流水线。

从任务到结论，每一步都有输入、输出、失败处理；任何一步不通过，都不会进入下一步。

01

任务生成与登记

把需求翻译成可执行任务，登记到 191 行台账（ID、来源、依赖、验收点）；任务不是「一句话」，是可复现的工件。

02

冒烟测试

76 任务 × 38 模块矩阵，每个格点跑一次最小验证；先证明「能跑」，再谈「跑得对」。

03

数据集构建

转成 Harbor 任务格式（record / replay），独立 apex-eval 队列 + 独立 schema，与生产队列物理分离。

04

评测执行

按 DD / PP / DP / VM / CD 五个阶段跑评测；评测器在 Harbor 沙箱外，被测代码在沙箱内。

05

指标采集

三平面指标：Pushgateway（推送）/ Prometheus（时序）/ Langfuse（追踪）；批次打 tag，异常 fail-loud。

06

评分汇总

按 rubric 汇总五阶段得分；每个扣分点锚到 file:line，可复核、可争论。

07

数据回流

失败样本回流成新任务 / 新规则；评测不是终点，是下一轮的起点。

02 / Data Pipeline

数据管线设施：让评测可复现。

评测最怕「这次过了、下次不过」。数据管线的职责，是把不确定性钉死在格式、队列、指标、骨架四件事上。

Harbor 任务格式

record / replay

任务统一成 Harbor 格式：record 记录环境与输入，replay 在隔离沙箱里重放。同一任务，任何机器上结果一致。

独立队列

apex-eval + 独立 schema

评测走独立队列与独立 schema，不与生产任务混跑；生产抖动不会污染评测基线。

三平面指标

Pushgateway / Prometheus / Langfuse

推送、时序、追踪三个平面各司其职；指标带批次 tag，能按批次、按任务、按阶段下钻。

Eval Skeleton

registration.json + analyze.ipynb

每个新评测任务套同一套骨架：注册、运行、分析三段式；新人接手不用重新发明流程。

批次与台账

批次 tag + fail-loud + 191 行台账

每批评测有唯一 tag；异常不静默，直接 fail-loud；191 行台账记录每个任务的来龙去脉。

隔离

评测沙箱与生产物理隔离

评测跑在 Harbor，生产跑在 bubblewrap；两套环境不共享状态，评测结果才可信。

03 / Rubric

五阶段 rubric。

金标准 + 结构门：不是「看起来对」，而是「覆盖点全不全、结论前置没前置、数据泄漏没泄漏」。

DD
问题空间覆盖：需求里每个问题点是否有对应实现，边界条件是否覆盖；rubric 锚到具体 file:line。
PP
结论前置：最终产出是否先给结论、再给证据；结构门要求「结论 → 依据 → 复现」。
DP
需求覆盖：任务描述里的每一条需求是否被满足；漏一条即扣分，不靠「整体感觉」。
VM
覆盖率 · rework · 跳步：测试覆盖多少、返工几次、有没有跳过关键步骤；跳步是长任务的头号杀手。
CD
数据泄漏 · 可复现：有没有把答案泄漏进上下文、结果能不能在干净环境复现；这两条不过，其他分再高也不算过。
04 / Judge Accuracy

评判准确性：judge 自己也得被评测。

如果 judge 会漂、会漏、会编，那所有分数都不可信。所以 judge 本身要过四道关。

零 IO 纯函数

judge 不读环境

评分函数不碰文件、不碰网络、不碰时钟；输入是 rubric + 证据，输出是分数 + 理由，可重放。

22-check 守卫

四类静默缺陷

22 项检查覆盖「分数缺失、理由为空、锚点不存在、阶段跳过」等静默缺陷；缺一项就不出分。

残片守卫

四道防线

截断、空证据、错位锚点、越界分数——四类残片各有守卫，防止「看起来有分，其实是垃圾」。

跨 judge 漂移

≤ 0.01

同一批任务换 judge 重跑，分数漂移必须 ≤ 0.01；超了说明 judge 不稳，先修 judge 再谈结果。

轮帽

32 轮上限

reviewer 最多 32 轮，超出即判失控；实测剔除 16/76 个失控样本，避免「无限返工」。

教训

首跑 4/12 假收敛

第一次跑 12 个任务，4 个「看起来收敛」其实是假收敛——这条教训直接催生了上面的守卫。

05 / Goals

三层评测目标。

评测要回答三个层次的问题：跑不跑得动、跑得对不对、跑得值不值。

可用性
跑得动：任务能进沙箱、能出结果、能在超时内完成；这是及格线，不是目标。
正确性
跑得对：五阶段 rubric 全过，CD（泄漏 / 可复现）必须过；正确性不能被「效率」换掉。
价值
跑得值：在正确的前提下，成本、时延、返工率是否可接受；这层决定能不能规模化。
