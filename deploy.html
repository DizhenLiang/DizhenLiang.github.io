Deploy / 部署全流程

从零到线上，
一条可重复的路径。

部署不是「跑起来就行」，而是「换个人、换个环境、隔一个月，还能一模一样地跑起来」。Apex-Agent 用模板 + 契约把这件事固化下来。

01 / Pipeline

7 步上线流程。

每一步都有明确的输入、输出和失败处理；任何一步挂了，都知道停在哪、怎么退。

01

环境准备

锁定 Python / Node / 容器运行时版本；检查磁盘、内存、网络出口；确认沙箱能力（bubblewrap / Harbor）可用。

02

依赖安装

从锁文件安装，禁止隐式升级；依赖装完跑一次 import 自检，防止「装上了但用不了」。

03

配置渲染

从 7 个模板渲染出当前 profile 的配置；所有路径走配置项，代码里零硬编码。

04

服务启动

按 profile（dev / staging / prod）启动；启动即自报状态，不靠人盯日志猜。

05

冒烟验证

跑一条最小任务：能进沙箱、能出结果、能写指标、能上报异常。四件事都过才算上线。

06

接入评测

把新环境挂到评测队列，跑一轮基线；基线不退化才允许接真实流量。

07

回滚预案

保留上一版配置与镜像；回滚是一键操作，且回滚后指标自动对比。

02 / Templates

模板驱动 + 逐层解耦。

7 个模板覆盖任务、工作区、Agent、评测、指标、日志、部署；层与层之间只认契约，不认实现。

7 个模板

任务 / 工作区 / Agent / 评测 / 指标 / 日志 / 部署

每个模板只描述「这一层要什么」，不关心别层怎么实现；换一层不影响其他层。

零硬编码

路径全部走配置

没有写死的绝对路径，没有「在我机器上能跑」。同一套代码换目录、换机器照常工作。

接口契约

层与层只通过契约通信

执行层、评测层、可观测层各自独立，只要契约不变，内部怎么改都行。

多 profile

dev / staging / prod 一套代码

同一套代码，按 profile 切换配置；开发、预发、生产不维护三份分支。

03 / Checklist

上线前，逐条打勾。

部署的可靠性，来自「每次都不跳过同一张清单」。

ENV
运行时版本锁定 · 沙箱可用 · 网络出口确认 · 磁盘/内存余量 ≥ 30%
CONFIG
7 个模板全部渲染成功 · 无硬编码路径 · profile 正确 · 密钥不落盘
SMOKE
最小任务跑通 · 指标有数 · 日志有痕 · 异常能上报
EVAL
基线一轮不退化 · 评测队列连通 · rubric 版本对齐
ROLLBACK
上一版可一键回滚 · 回滚后指标自动对比 · 回滚演练过至少一次
Why it matters

为什么部署值得单独讲。

长任务系统一旦上线，失败成本会被时间放大：跑了一夜才发现环境不对，比跑五分钟就报错贵得多。部署流程的价值，是把「环境不确定性」在上线前一次性消掉。

模板让配置可复现，契约让层可替换，profile 让环境可切换，回滚让试错可承受——四件事合起来，才叫「部署全流程」，而不是「部署脚本」。
