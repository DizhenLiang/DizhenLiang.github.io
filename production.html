01 / The Flywheel

飞轮：五个环节咬合。

每一轮都把「失败」变成下一轮的「数据」。没有一次性脚本，只有持续变强的机器。

01

任务定义

把模糊需求翻译成可验收的任务：边界、约束、验收标准。任务本身是可执行、可复现的工件，不是一句话。

02

隔离工作区

每个任务一个干净工作区，bubblewrap 限制文件系统 / 网络 / 进程。上一轮的残留不会污染下一轮。

03

智能体执行

6-Agent 运行时协作：拆解、执行、探测、评审、规划、验证，各自边界清晰，输出可追溯。

04

独立评测

评测器与被测代码物理隔离，跑在 Harbor 沙箱里；评分按五阶段 rubric，锚到 file:line。

05

数据回流

轨迹、指标、经验回流成下一轮的任务与规则。跑得越多，飞轮越稳。

02 / Runtime

6-Agent 运行时。

不是一个大模型包打天下，而是六个角色各管一段：谁拆、谁做、谁探、谁评、谁规划、谁验证。

Delegator

拆解与分派

把任务拆成有边界的子任务，分给合适的角色，并维护依赖顺序。

Worker

执行

在隔离工作区里动手：读代码、改文件、跑命令、拿结果。

Prober

探针

构造行为测试与边界用例，判断「改没改对、覆没覆盖」。

Reviewer

评审

按 rubric 独立评分，给出可定位的问题，而不是一句「感觉不对」。

Planner

规划

在长任务里维持全局目标，防止走偏、跳步、重复劳动。

Verifier

验证

用检查器 / 构建 / 契约做最终判定，守最后一道门。

03 / Isolation

双沙箱：执行与评测物理隔离。

执行沙箱管「能不能跑」，评测沙箱管「算不算对」。两个平面不共享内存、不共享文件系统。

执行沙箱
bubblewrap：限制文件系统、网络、进程，任务代码跑在里面，拿不到宿主环境。
评测沙箱
Harbor：被测代码跑在评测沙箱内，评测器跑在沙箱外——数据不泄漏，答案也改不了。
隔离收益
防数据泄漏、防「改评测器过题」、防跨任务污染；每个任务都是可复现的干净起点。
04 / Self-healing

自愈 · 巡检 · 熔断。

长任务最怕的不是报错，是「静默错误」——跑完了，但结果是错的。三层兜底把它提前暴露。

自愈

重试 + watchdog

失败自动重试（最多 2 次）；卡死的任务由 watchdog 超时回收，不让一个任务拖垮整条队列。

巡检

1,648 行 · 1,745 tests

巡检代码本身被测试覆盖，检查「该有的日志有没有、该报的异常报没报、状态是否一致」。

熔断

连续 5 次失败触发

同一类失败连续出现时自动熔断，先停、再看、再修——而不是让错误雪崩。

验证

36 次预置故障

主动注入故障，验证「告警会不会响、回滚会不会生效、轨迹会不会留痕」。

05 / Observability

可观测：三平面 + 全量日志。

一条轨迹要能回答：哪一步慢了、哪一步错了、哪一行代码导致的。

指标平面
Pushgateway 推送 + Prometheus 时序：任务吞吐、成功率、时延、成本。
追踪平面
Langfuse：LLM 调用链、token、上下文窗口，逐跳可回放。
日志平面
40/40 日志覆盖 + 40/40 异常上报；1,131 次异常上报真实落地，不是「设计里写了」。
